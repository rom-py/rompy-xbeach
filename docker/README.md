# XBeach docker image

This directory builds a Docker image that runs [XBeach](https://xbeach.readthedocs.io/) on workspaces generated by rompy-xbeach. With it, you don't need to compile XBeach yourself.

The image is published as **`ghcr.io/rom-py/xbeach`**:

| Tag | Contents |
|---|---|
| `1.24.6057-halloween-beta` | XBeach release v1.24.6057 "Halloween" (BETA) |
| `trunk-r<revision>`, e.g. `trunk-r6147` | XBeach SVN trunk at that revision, the last revision that changed the trunk |
| `latest` | The newest `trunk-r<revision>` image |

Release tags are `<version>-<release name>`, following the Deltares SVN tag names. Pin a release or trunk tag for reproducible runs, since `latest` moves when a new trunk revision is published. Every image is tested with workspaces generated by rompy-xbeach before it is published.

Each image contains XBeach built with NetCDF output, in two builds, plus the Open MPI runtime:

| Command | What runs |
|---|---|
| `xbeach` | The MPI build when started by `mpirun` with 2 or more processes, the serial build otherwise |
| `xbeach-serial` | The serial build |
| `xbeach-mpi` | The MPI build, which refuses to run on a single process |

With `mpirun -n N`, XBeach uses one process for output and `N - 1` for computation.

## Running a generated workspace

### From rompy-xbeach

Use rompy's Docker backend:

```python
from rompy.backends import DockerConfig

modelrun.run(DockerConfig(image="ghcr.io/rom-py/xbeach:trunk-r6147", executable="xbeach"))
```

To run with MPI across 4 processes:

```python
modelrun.run(
    DockerConfig(
        image="ghcr.io/rom-py/xbeach:trunk-r6147",
        executable="xbeach",
        mpiexec="mpirun",
        cpu=4,
    )
)
```

### From the command line

Run these commands from inside the workspace directory:

```bash
docker run --rm -v "$PWD":/data ghcr.io/rom-py/xbeach:trunk-r6147 xbeach
docker run --rm -v "$PWD":/data ghcr.io/rom-py/xbeach:trunk-r6147 mpirun -n 4 xbeach
```

> [!NOTE]
> The container runs as root, so XBeach output files in the workspace are owned by root. On Linux, add `--user "$(id -u):$(id -g)"` to `docker run` to keep your own ownership.

## Building locally

Build the trunk at a revision, or a release from its SVN tag:

```bash
docker build -t xbeach docker
docker build -t xbeach --build-arg XBEACH_REVISION=6147 docker
docker build -t xbeach:1.24.6057-halloween-beta \
  --build-arg XBEACH_SVN_PATH=tags/2023-10-31-XBeach-v1.24.6057-Halloween_BETA \
  --build-arg XBEACH_REVISION=HEAD --build-arg XBEACH_VERSION=1.24.6057-halloween-beta \
  docker
```

To check that an image runs rompy-xbeach workspaces (stationary, surfbeat and MPI):

```bash
python docker/test_image.py xbeach
```

## Publishing

The [docker workflow](../.github/workflows/docker.yml):

- **Pull requests** touching this directory: build and test every image.
- **Pushes to `main` or `output`, and new tags**: publish `trunk-r<revision>` and move `latest` to it, if the trunk has changed since the last published image. If this directory changed, all images are rebuilt and published.
- **Manual runs**: build, test and publish all images.

To add a release, add a line to [`releases.txt`](releases.txt). Only releases with the `wbctype` keyword (XBeachX, v1.23, and later) can run rompy-xbeach workspaces. To publish a specific trunk revision, run the workflow manually with the `trunk_revision` input.
