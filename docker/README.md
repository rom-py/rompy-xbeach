# XBeach docker image

This directory builds a Docker image that runs [XBeach](https://xbeach.readthedocs.io/) on workspaces generated by rompy-xbeach. With it, you don't need to compile XBeach yourself.

The image is published as **`ghcr.io/rom-py/xbeach`**:

| Tag | Contents |
|---|---|
| `r6147` | XBeach SVN trunk revision 6147 |
| `latest` | the most recent published revision |

The image contains XBeach built from the Deltares SVN trunk with NetCDF output, in two builds, plus the Open MPI runtime:

| Command | What runs |
|---|---|
| `xbeach` | The MPI build when started by `mpirun` with 2 or more processes, the serial build otherwise |
| `xbeach-serial` | The serial build |
| `xbeach-mpi` | The MPI build, which refuses to run on a single process |

With `mpirun -n N`, XBeach uses one process for output and `N - 1` for computation.

## Running a generated workspace

### From rompy-xbeach

Use rompy's Docker backend:

```python
from rompy.backends import DockerConfig

modelrun.run(DockerConfig(image="ghcr.io/rom-py/xbeach:r6147", executable="xbeach"))
```

To run with MPI across 4 processes:

```python
modelrun.run(
    DockerConfig(
        image="ghcr.io/rom-py/xbeach:r6147",
        executable="xbeach",
        mpiexec="mpirun",
        cpu=4,
    )
)
```

### From the command line

Run these commands from inside the workspace directory:

```bash
docker run --rm -v "$PWD":/data ghcr.io/rom-py/xbeach:r6147 xbeach
docker run --rm -v "$PWD":/data ghcr.io/rom-py/xbeach:r6147 mpirun -n 4 xbeach
```

> [!NOTE]
> The container runs as root, so XBeach output files in the workspace are owned by root. On Linux, add `--user "$(id -u):$(id -g)"` to `docker run` to keep your own ownership.

## Building locally

```bash
docker build -t xbeach docker
docker build -t xbeach --build-arg XBEACH_REVISION=6147 docker
```

## Publishing

The [docker workflow](../.github/workflows/docker.yml) builds the image for every pull request that touches this directory. On pushes to `main` or `output`, it also pushes the image to GHCR.

To publish another XBeach revision, run the workflow manually with the `xbeach_revision` input.
